# EmDash schema is data, not code

Collections and fields live in `_emdash_collections` / `_emdash_fields` in `apps/storefront/data.db` (git-ignored), and each
collection is a table `ec_<slug>`. Creating one through the admin, `emdash schema create` / `add-field` or the MCP
`schema_*` tools changes only that database.

- **Keep it reproducible:** add the collection (and a sample entry under `content`) to `seed/seed.json` too; check it
  with `pnpm exec emdash seed seed/seed.json --validate`. The seed runs once, in the setup wizard, so an existing
  database is not changed by editing the file.
- **Types:** `emdash-env.d.ts` is regenerated by the dev server and by `pnpm exec emdash types --url http://localhost:4360`
  — run it after a schema change, or `getEmDashEntry("home", …)` is not typed.
- **CLI auth on localhost:** `emdash` commands need no token under `astro dev`; they sign in through the dev bypass
  (`emdash whoami` shows `Auth: dev-bypass`). `content update` needs `--rev` from `content get`.
- **A new page-level setting is a collection, not a site setting:** `getSiteSettings()` has a fixed shape (title,
  tagline, logo, favicon, social, SEO). The homepage intro image is the `home` collection (one entry, slug `home`),
  edited under Content → Homepage.
- **Dev style cache:** after editing a page's `<style>` the dev server once kept serving the old CSS; `astro dev stop`
  and start again fixed it.
